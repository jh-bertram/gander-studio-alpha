       LAYOUT IDIOM CHOICE (SC2)
       ═══════════════════════════════════════════════════════════════════════
       Chosen idiom: VERTICAL TIMELINE LIST with a pinned per-surface summary
       header.

       Rationale: The data is time-series XP accumulation — each sprint is a
       discrete event on a time axis with a structured breakdown per surface.
       A vertical timeline list (most-recent first) is the standard idiom for
       this shape. React Flow (node-edge graph) is explicitly wrong here: there
       are no edges between sprints and no spatial relationship to express.
       A pure table would obscure the chronological narrative; a list of sprint
       cards preserves the temporal reading order while accommodating variable
       xp_gained array lengths cleanly.
  ═══════════════════════════════════════════════════════════════════════════ -->

      Neither LevelsAdvancedSection nor NewCapabilitiesSection renders.
      No placeholder text is shown — the section is simply absent.
      Rationale: early sprint entries may have no promotions; showing an empty label
      wastes space and creates visual noise. Absence is semantically correct.
      (SC5 — empty-array handling)
    </state>

      When only one of levels_advanced / new_capabilities is non-empty:
      Only the non-empty section renders. The empty section is suppressed.
    </state>

      When a surface has not appeared in any sprint's xp_gained (count = 0):
      The SurfacePill still renders (all 8 always shown for completeness).
      SurfaceXpCount shows "0" in color var(--wm) (muted) rather than var(--wd).
      SurfaceDot opacity: 0.4 (muted, not hidden).
      Rationale: hiding a surface would imply it doesn't exist; showing it muted
      communicates "not yet touched" rather than "not applicable."
    </state>

      Transition: background 120ms ease.
    </state>

    </state>

    </state>
  </states>

  <accessibility_spec>
    <contrast_pairs>
      <!-- Body text: var(--wd) = rgba(255,255,255,0.72) on var(--sfm) = #122420 -->
      <!-- Effective white 72% opacity on dark bg ≈ #b8d2cd on ~#122420. -->
      <!-- Approximate luminance: fg ~0.48, bg ~0.012 → ratio ~(0.48+0.05)/(0.012+0.05) ≈ 8.5:1 -->
      <pair element="Body text (XpGain delta, LevelItem)" foreground="--wd" background="--sfm" ratio="~8.5:1" wcag_level="AAA" />

      <!-- Section heading h1: var(--w) on var(--void) = #ffffff on #070d0c -->
      <!-- Luminance: 1.0 / 0.0016 → ratio = (1+0.05)/(0.0016+0.05) ≈ 20.4:1 -->
      <pair element="h1 heading" foreground="--w" background="--void" ratio="~20:1" wcag_level="AAA" />

      <!-- SprintIdLabel: var(--mt) = #5499b5 on var(--sfm) = #122420 -->
      <!-- Luminance mt: ~0.093, sfm: ~0.012 → ratio ≈ (0.093+0.05)/(0.012+0.05) ≈ 2.3:1 -->
      <!-- FAILS AA for normal text. Mitigate: render sprint_id in fontFamily var(--fm),
           fontSize 14px BOLD (large text threshold is 18px normal or 14px bold per WCAG).
           At bold 14px it qualifies as large text → AA threshold drops to 3:1 → still borderline.
           FE must render sprint_id at 15px+ bold OR pair with var(--wd) body weight.
           DESIGN DECISION: sprint_id uses var(--mt) at 15px bold — large text AA = 3:1 threshold.
           Ratio 2.3:1 still fails large text AA. Alternative: use var(--w) for sprint_id text
           and accent only the left-border pip with var(--mt). FE MUST choose the var(--w) path
           for the sprint_id text itself, with var(--mt) reserved for the left-border accent.
           This correction is recorded here and supersedes the naive --mt assignment above. -->
      <pair element="SprintIdLabel (sprint_id text — corrected to --w)" foreground="--w" background="--sfm" ratio="~20:1" wcag_level="AAA" />

      <!-- SurfaceTag text: var(--wd) on var(--sfh) = rgba(255,255,255,0.72) on #1a3530 -->
      <!-- Background sfh slightly lighter than sfm. Ratio ≈ 7:1 -->
      <pair element="SurfaceTag text" foreground="--wd" background="--sfh" ratio="~7:1" wcag_level="AAA" />

      <!-- Section labels: var(--wm) = rgba(255,255,255,0.38) on var(--void) -->
      <!-- This is marginal for normal text. Section labels are uppercase, letter-spaced,
           and serve as category dividers (not body text). They should be 11–12px uppercase.
           At that size WCAG requires 4.5:1. rgba(255,255,255,0.38) on #070d0c ≈ 5.5:1 — passes AA. -->
      <pair element="Section labels (SURFACE COVERAGE etc.)" foreground="--wm" background="--void" ratio="~5.5:1" wcag_level="AA" />

      <!-- SubLabels: var(--my) on var(--sfm) -->
      <!-- var(--my) = #e8c840 (yellow). On #122420: luminance my ~0.513, sfm ~0.012 →
           ratio ≈ (0.513+0.05)/(0.012+0.05) ≈ 9.1:1 -->
      <pair element="SubLabel LEVELS ADVANCED" foreground="--my" background="--sfm" ratio="~9:1" wcag_level="AAA" />

      <!-- SubLabels: var(--mg) on var(--sfm) -->
      <!-- var(--mg) = #4caf7d. On #122420: luminance mg ~0.177, sfm ~0.012 →
           ratio ≈ (0.177+0.05)/(0.012+0.05) ≈ 3.7:1 — FAILS normal text AA (4.5:1).
           Mitigate: render at 12px uppercase bold (large text at bold 12px may still not qualify).
           DESIGN DECISION: render NEW CAPABILITIES sublabel at 13px bold or increase to
           var(--cgr) = #7ecfb0. cgr luminance ~0.33 → ratio ≈ (0.33+0.05)/(0.012+0.05) ≈ 6.1:1 — passes.
           Use var(--cgr) for the NEW CAPABILITIES sublabel text. var(--mg) only for the left-border pip. -->
      <pair element="SubLabel NEW CAPABILITIES (corrected to --cgr)" foreground="--cgr" background="--sfm" ratio="~6:1" wcag_level="AA" />

      <!-- Error title: var(--redb) = #cf3c3c on var(--sfm) = #122420 -->
      <!-- Luminance redb ~0.04, sfm ~0.012 → ratio ≈ (0.04+0.05)/(0.012+0.05) ≈ 1.5:1 — FAILS. -->
      <!-- Correction: use var(--w) for error title text, var(--redb) for left accent only.
           This matches how GraphPage handles the error title (redb is already used there —
           but the existing GraphPage has the same potential contrast issue on sfm.
           Per the GraphPage precedent we accept var(--redb) for large-text error titles
           at 16px; large text AA threshold = 3:1. Estimated ratio at 1.5:1 still fails.
           FE MUST render error title at var(--w) with var(--redb) border only.
           Record as a known GraphPage issue to fix in a future polish sprint.) -->
      <pair element="Error card title (corrected to --w)" foreground="--w" background="--sfm" ratio="~20:1" wcag_level="AAA" />
    </contrast_pairs>
