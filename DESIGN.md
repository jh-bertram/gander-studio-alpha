# Design System — Gander Studio
> Version: 1.1.0 | Updated: 2026-06-20 | Generated by: generate-design

## Constitution

Non-negotiable rules for this app's visual identity.

- **Dark mode only:** never use white or light-gray backgrounds — minimum surface is `#0f1117`
- **No CRT scanlines:** the `body::before` scanline overlay is prohibited in Studio Clarity; remove before any sprint ships
- **No glow shadows:** `box-shadow` glow effects (e.g. `0 0 12px rgba(...)`) are prohibited; use `1px solid` border-on-hover instead
- **No serif fonts:** Optima and Palatino are deprecated; all text uses `Geist Variable` at varying weights
- **Icons from lucide-react only:** no inline SVG, no other icon libraries
- **Minimum touch target: 44×44px** for all interactive elements
- **Role colors are preserved:** the materia color system (green/yellow/blue/purple/red/orange) is functionally meaningful and must not be changed without a design decision record

## Decision Record A — Shadcn @layer base Token Remap to FF7 Runtime (s1, 2026-06-20)

**Sprint:** prog-studio-vision-2026-06-s1-token-root-fix
**Author:** UI Designer (ui-designer agent)
**Status:** RATIFIED — supersedes the Studio Clarity migration direction for this token set (see Supersession Statement below)

### Context

`globals.css` contains two `:root` blocks. The first (lines 7–50) defines FF7 runtime tokens (`--void`, `--sf`, `--sfm`, `--sfh`, `--mt`, `--bd`, `--bdb`, `--w`, `--wm`, `--mg`, `--my`, etc.). The second (lines 188–222, inside `@layer base`) is stock Shadcn light-mode boilerplate: `--background: oklch(1 0 0)` (white), `--foreground: oklch(0.145 0 0)` (near-black), and peers. The `.dark` block at lines 223–255 is never applied (zero `.dark` className sites in the app). The light-mode `@layer base` values therefore always win, causing Shadcn primitives (`ui/input.tsx`, `ui/textarea.tsx`, `ui/dialog.tsx`, `ui/button.tsx`) to render near-black text on the FF7 dark surface — invisible to the user.

The fix is to remap every `@layer base` `:root` token to point at the corresponding FF7 runtime token using `var()` references. This makes the FF7 `:root` block the single source of truth; downstream contrast bumps to `--wm` and `--mt` (Decision Record B and p3) propagate automatically via the `var()` chain without any component edits.

### Supersession Statement

The Studio Clarity migration described in **Design Integrity Notes** (lines 123–125 of this file) and the minimum-surface floor declared in **Constitution line 8** (`#0f1117`) document a planned replacement of FF7 tokens with semantic `--color-*` tokens. **That migration was never executed.** At HEAD of branch `prog-studio-vision-2026-06`, all ~102 component and constant usages reference FF7 runtime tokens (`var(--void)`, `var(--mt)`, `var(--wm)`, etc.); the `--color-*` names exist in DESIGN.md only and have zero CSS usage sites in the codebase. Ratifying the FF7 runtime as canonical is not a cosmetic choice — it aligns the design record with the actual rendered state and is a prerequisite for the contrast remediation in this sprint. The Studio Clarity migration is formally superseded. Future sprints that wish to resume migration must author a new decision record and a phased component-migration plan; they may not treat the Design Integrity Notes (lines 123–125) as a currently-active directive.

### .dark Block Decision

**Decision: REMOVE** the `.dark` block (globals.css lines 223–255).

Rationale: the `.dark` className is applied nowhere in the app (verified at HEAD, zero grep hits). The block is dead code that creates maintenance confusion — a reader might assume dark-mode theming is active when it is not. Removing it eliminates the confusion and shrinks the CSS payload. If dark/light toggling is added in a future sprint, a new decision record must accompany its reintroduction with explicit `.dark` mount sites.

### Contrast Remediation Targets (resolves DEFERRED-005)

**DEFERRED-005** (docs/deferred-work.md line 64) identified two below-AA pairings. This record specifies the exact target values. Execution is owned by sprint s1-p3 (frontend-engineer).

#### Target 1 — --wm (muted/placeholder text alpha)

**Problem:** `--wm: rgba(255,255,255,0.38)` composited on the lightest dark surface `--sfh` (#1a3530) yields approximately **3.22:1** — below the WCAG AA threshold of 4.5:1 for normal text.

**Method:** WCAG relative luminance formula. Composited color on `--sfh` at α=0.38:
- Effective RGB ≈ (113, 130, 127) → L ≈ 0.2099
- Contrast = (0.2099 + 0.05) / (0.0308 + 0.05) = 0.2599 / 0.0808 = **3.22:1** (FAIL)

**Decision:** Raise alpha to `0.55`.

At α=0.55 on `--sfh`:
- Effective RGB ≈ (152, 164, 162) → L ≈ 0.3587
- Contrast = (0.3587 + 0.05) / (0.0308 + 0.05) = 0.4087 / 0.0808 = **5.06:1** (PASS AA)

**Target value:** `--wm: rgba(255, 255, 255, 0.55)`

Checked surfaces (α=0.55 composited):
| Surface | Surface L | wm L (composited) | Contrast | WCAG |
|---|---|---|---|---|
| `--sfh` (#1a3530) | 0.0308 | 0.3587 | 5.06:1 | AA |
| `--sfm` (#122420) | ~0.016 | ~0.395 | ~7.0:1 | AAA |
| `--sf` (#0d1a18) | 0.0089 | ~0.400 | ~7.6:1 | AAA |
| `--void` (#070d0c) | 0.0036 | ~0.406 | ~8.3:1 | AAA |

`--sfh` is the binding worst case. All other surfaces pass by a larger margin.

#### Target 2 — --mt (Mako Teal) text on --sfh

**Problem:** `--mt: #5499b5` on `--sfh` (#1a3530) yields approximately **4.08:1** — below WCAG AA 4.5:1 for normal-weight text.

**Strategy choice:** Strategy (a) — lighten the single `--mt` token value. Strategy (b) — introduce a separate `--mt-text` token — is a trap this sprint: with ~102 usage sites referencing `var(--mt)` for text, border, ring, and nav-active roles, adding a new token without a component migration leaves all rendered text pairings unchanged. Strategy (a) changes the VALUE at the definition site and propagates immediately to all consumers.

**Risk of strategy (a):** `--mt` is used for both text AND UI-component roles (border, ring, focus ring, scrollbar thumb, nav-active accent). Lightening it shifts those appearances. The constraint is that the new value must still clear 3:1 for large-text and UI-component roles on the surfaces where it appears as a border/ring.

**Decision:** Raise `--mt` to `#6db0c8`.

Verification:
- `#6db0c8` on `--sfh` (#1a3530): L(6db0c8) ≈ 0.3849; contrast = (0.3849+0.05)/(0.0308+0.05) = **5.38:1** (PASS AA for normal text)
- `#6db0c8` on `--void` (#070d0c) as border/ring: contrast = (0.3849+0.05)/(0.0036+0.05) = **8.12:1** (PASS — well above 3:1 for UI components)
- `#6db0c8` on `--sf` (#0d1a18): contrast = (0.3849+0.05)/(0.0089+0.05) = **7.49:1** (PASS)

Both the text-legibility requirement (>=4.5:1) and the UI-component requirement (>=3:1 for borders and rings) are satisfied by `#6db0c8`.

**Target value:** `--mt: #6db0c8`

The `--mtd` (dim variant, currently `#3a6f8a`) should also be lightened proportionally to maintain visual hierarchy. Recommended target: `#5a96aa`. FE (p3) must compute and verify the dim variant's pairing against its usage contexts (scrollbar thumb, pressed state); this record specifies the direction, not the exact dim value — p3 owns the final number subject to the same 3:1 UI-component floor.

### prefers-reduced-motion Fallbacks

Every s4 animation resolves to a static legible state under `@media (prefers-reduced-motion: reduce)`. p1 must include a single suppression block after all class definitions.

| Class | Reduced-motion fallback | Information preserved without motion? |
|---|---|---|
| `.skeleton-shimmer` | `animation: none; background: var(--sfm)` | Yes — static rectangle communicates loading via shape + border |
| `.panel-in` | `animation: none; opacity: 1; transform: none` | Yes — panel at final position, fully legible |
| `.timeline-bar-enter` | `animation: none; opacity: 1; transform: scaleX(1)` | Yes — all bars at full width immediately |

Pre-existing inline-style animations (`shimmer` on ShimmerBox, `pulse-opacity` + `spin` on ProgressionPage) are also suppressed in the reduced-motion block using attribute selectors targeting the `animation:` style value. p1 may alternatively refactor those callsites to use CSS classes instead of inline styles — cleaner but p1's implementation decision.

### Duration Rationale

- **180ms (panel-in):** dialog entrances read as snappy but physically grounded. Matches the lower bound of the 150–200ms dialog-entrance convention.
- **200ms (mode-crossfade):** primary navigation action should feel decisive. Slightly longer than panel-in so the transition is registered without feeling like a page load.
- **240ms (timeline-bar-enter):** bar geometry carries information (duration, overlap). Slightly slower entrance lets the reader track which bar is which as each enters sequentially.
- **600ms (marching-ants):** fast enough to read as "live" without being distracting. Linear easing prevents the acceleration artifact that eased infinite loops produce.
- **900ms (level-up-flash):** celebration flash wants to be noticed but not linger. Peak at 40% keyframe then fade — burst shape reads as an event, not a fade-in.
- **1.6s (playhead pulse):** calm ambient signal. Distinct from 600ms marching-ants: two different animation speeds provide hierarchy (marching = this bar is running; pulse = here is now).

### Token Basis for level-up-flash

`--my: #e8c840` → RGB (232, 200, 64). The `level-up-flash` keyframe uses `rgba(232, 200, 64, ...)` derived directly from this token's hex value. No raw hex invented. The flash color matches the LEVELS ADVANCED section label and the command-agent materia — intentional semantic alignment.
